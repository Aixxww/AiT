## 3. 与策略 Prompt 的关系

本轮平仓不是因为 Prompt 写了“移动止盈”后被 LLM 在下一个 15m 周期识别执行，而是交易引擎的独立持仓保护器在轮询周期之外执行。

因此：

- Prompt 里的 `take_profit` 应理解为 TP1 参考，不应要求 LLM 输出非标准 `TP2` 或 `trailing_stop` 字段；
- TP1/TP2/移动保护应由后端执行层完成；
- LLM 的主要职责是给出方向、入场价、止损、近端止盈和信心分；
- 后端负责在实盘价格变化中保护浮盈，避免 15m 主循环过粗。

## 4. 本轮暴露的问题与修复

此前 #102 出现“刚开仓即被移动保护平仓”的风险，根因是保护器过于敏感。当前已调整为自适应保护：

- 空仓或无有效持仓时降低检查频率；
- 普通持仓使用基础频率；
- 只有达到 TP1 附近或已经部分止盈后，才进入快速保护；
- 未触发 TP1 前的回撤保护增加最短持仓时间和当前正收益要求。

这能降低刚开仓被噪音扫出的概率，同时保留盈利订单的快速保护能力。
